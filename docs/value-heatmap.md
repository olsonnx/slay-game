# Province value filter — 13 October 2026

Press **F**, or the grid icon beside the camera button, to toggle the value filter. Tab independently changes top-down/3D. Both keys are rebindable in Controls; the existing icon and legend are retained.

The filter now uses the **actual raised terrain**, including its 0.56-unit earth sides, original cap geometry, kingdom joins, lighting and shadows. It no longer draws a flat replacement island. Water/Sky stays visible with its original shader and saved preferences. A softer terracotta/red, warm yellow and green palette tints the lit tile surfaces by value; zero-value surfaces are black. The highest current positive value is green, except a map containing only value 1 remains red. The live legend follows development and the visible board's maximum.

Buildings, mountains, graves and small ground details remain as subdued landmarks. Their materials are duplicated/cached and desaturated; zero-value mountain/bridge details are darkened while retaining their geometry. Units, trees, mana/ward clutter and action previews are hidden. Exact numbers appear on the hovered province, with value-first tooltips, rather than across every tile. Narrower faction-coloured boundary strokes preserve kingdom visibility without a diagram-like grid. Hidden trees/units do not capture mouse hits; visible landmarks retain their normal hit footprints and resolve to province inspection.

`value_heatmap.gd` applies/restores material overrides on existing terrain/prop nodes. Shared materials are never modified in place. Original overrides and visibility are tracked by instance, with explicit unit/ward roles rather than node names. Playback replacements and newly built props are filtered on visible-board signals; stale node references are pruned. Occupation can temporarily leave both a defeated defender and a reparented traveler registered: restoration keeps the traveler and does not revive the defender. The filter uses `board.cells`, not preplanned authoritative ownership.

Hover-number nodes and a single vertex-coloured boundary mesh are retained. Values only change tint/text; boundaries rebuild on topology/owner/kingdom/bridge changes. No replacement tile meshes or per-frame full-map rebuilding are used. Tree grouping lives in the shared `BoardAssets.add_tree` helper, keeping gameplay and menu geometry identical while allowing selective foliage hiding. This is a transient information view, not a saved appearance preference for the decorative menu. New games/island transitions clear it.

The latest border repair uses full-length hex edges with rounded endpoint joins from shared `flat_strokes.gd`, also used for movement-area borders. This closes the corner gaps caused by independently inset segments. Dark and colored boundary layers have sufficient vertical separation to avoid depth speckling. Final verification after the repair: heatmap **38**, indicators **337**, input **42**, performance **284**, presentation **5,080**, all passed. Native Water/angled and Sky/overhead minimum-window previews inspected.

The normal default remains F. Existing custom F bindings from older controls files are preserved through a free heatmap fallback shown in Controls. Restore defaults returns the action to F. Province value is separate from income: trees/graves can block earnings without reducing value, and houses/upkeep do not change it.

Verification: all **20 affected suites from animation onward passed**, resuming at the menu suite after correcting shared tree grouping. The final filter suite passed **38 checks**, including original 3D mesh identity, standard lit shading, retained mountain relief, selective hiding, hover-only numbers, exact material restoration, renamed defender restoration during capture, live values/kingdom borders, both backgrounds and rebinding. Presentation passed 5,080 checks, terrain 2,498, UI layout 106 and menu-background geometry 4,324. Simulation-only AI/general suites were not repeated for this visual revision; the preceding full 22-suite run remains historical. Editor scan completed cleanly.

Native previews inspected: `artifacts/preview_heatmap_water_modern.png`, `preview_heatmap_small_water_modern.png` and `preview_heatmap_sky_modern_top.png`. Reproduce with `tools/preview.gd -- --modern --water --heatmap`, adding `--small-window` or `--top-down`; replace Water with Sky as needed.

Future watchpoints: active sync traverses retained prop meshes on board changes, and filtered material variants are cached by original resource and treatment. Profile before adding larger maps or more material effects; no GPU/FPS benefit is claimed. The scale is relative to the current maximum, so development can recolour unchanged provinces. Keep restoration tests when adding new prop types, material animations or unit reparenting paths.

Repeated-switch performance repair (13 October): static batching previously evicted material feature keys whenever a material was absent from the current view. Alternating normal/filtered overrides therefore repeated hundreds of full material-property scans on every switch. Feature keys now survive for the resource's lifetime through weak references; sync removes expired keys without retaining discarded materials. The seeded Modern Large/six-kingdom probe (`tools/heatmap_toggle_probe.gd`) measured warmed on/off pairs at roughly 330–390 ms headless before, 63–74 ms headless after, and a 69.180 ms native median after. These are CPU toggle timings, not steady-state FPS. All 202 native switches retained stable node/resource/material counts. Static batching adds 60 real shortcut pairs, zero warmed material rescans, bounded caches, exact restoration and expired-resource cleanup checks. Affected headless suites passed: static batching 1,472; heatmap 38; editor 131; menu rendering 55,012; performance 458.

## Prepared switching — 24 October 2026

Map loading now prepares the province-value rendering before the island is revealed. Both the normal and value views retain their static render batches and source indexes. The loading cover stays up while value materials and borders are drawn for three native frames, then the normal view is restored. The time appears in `game.startup_timings.value_view_prepare_ms`.

Switches reuse these uploads rather than traversing and rebuilding the island. At most one inactive view is retained alongside the active view. Canonical source nodes, original materials, visibility restoration, picking and animation ownership stay in place. Restoring a cached view rebinds visual animation slots and current shadow/detail settings. The cache is discarded with its board.

Visible changes invalidate the affected cached tiles, including value-only changes that do not change normal terrain geometry. Returning to the value view updates changed regions while reusing unaffected props. A new maximum refreshes all value colors, including distant untouched regions; topology, material-style changes and removed sources also invalidate the relevant uploads. Labels, borders and muted materials remain retained. Cached information comes from the visible board, never future authoritative playback.

On this machine, a native Forward+ seeded Standard map (237 tiles, seed 42, six kingdoms) measured first activation at **327.267 ms before / 7.946 ms after preparation**. Later activation medians were **106.487 / 8.526 ms**, and deactivation medians **97.963 / 8.342 ms**. These are CPU switch timings, not steady-state FPS or guarantees for other hardware. Native preparation took about **588 ms** under the loading screen. A prepared 1,000-tile Huge board measured **27.796 ms** for first activation and about **28 ms** for repeated switches; its preparation took about **1.67 seconds**. Huge can still drop frames when switching.

A 202-switch headless stress run retained exactly two renderings, with stable 2,299 nodes, 160 resources and 66 muted-prop materials, zero switch-triggered batch synchronizations, and zero terrain rebuilds. Native on/off screenshots were inspected: `artifacts/value-mode-large-on.png` and `artifacts/value-mode-large-off.png`.

Reproduce CPU and cache measurements with `tools/heatmap_toggle_probe.gd`; add `-- --huge` for 1,000 tiles, or `-- --cold` to skip loading preparation. This probe reports preparation time, switch pairs, source scans, terrain rebuilds and retained views. Regression coverage includes the first switch after real loading/entry, repeated switches, visible captures, normal-mode value changes both with and without a new maximum, and distant-chunk recoloring.
