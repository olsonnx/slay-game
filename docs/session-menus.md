# Session menus

Island appearance settings must apply consistently to gameplay and the decorative menu landmass. Video settings include **Internal borders**, a saved 0–100% slider defaulting to 50%, applied immediately in both views, including while paused or while the menu is hidden. At 0% shared kingdom edges are seamless; at 100% they use the original rim width. Exterior/neutral/bridge edges stay distinct. Streamed rows retain their kingdom masks, with different chunks treated as separate islands. Both renderers use the same geometry/cache helper without regenerating terrain or props. The shared options panel is 600 px high and fits the minimum 960×620 window.

Quick Play setup separately selects **Map size**, **Kingdoms** and **Difficulty**. Default size/count is Tiny/four. Tiny, Small, Standard, Large and Huge support two through six kingdoms. The five options show approximate tile counts directly: 80, 150, 250, 500 and 1,000 respectively. Very Small is retired. Stable internal size IDs preserve existing map and replay generation; the old Large profile is now Standard and the old Very Large profile is now Large. Hover tooltips explain that land totals include mountains and vary with the seed and kingdom count. Huge is the tested 1,000-tile target with more frame-time headroom than 2,000 tiles at 1080p. Counts include the player. The 528 px setup panel fits the minimum window. Valid counts remain selected on size changes; an incompatible count is reduced to the size's maximum. The selected count travels through asynchronous preparation and is retained on restart and rules changes.

`scenes/app.tscn` is the application entry point. Its controller creates the lightweight main menu first, and instantiates `scenes/main.tscn` only for a Quick Play. The gameplay scene remains independently testable.

`session_menus.gd` owns the navigation state: main menu, pause, options, quit destinations and confirmation. The same `options_view.gd` is shared by the main and pause menus. Menu nodes process always, while each gameplay scene explicitly uses pausable processing; this prevents the application's always-active parent from accidentally keeping gameplay running.

Pause shows **Time played** and the current map's **Seed** beneath its title. Time uses the existing match clock, excluding solo pause time; online matches continue updating the displayed duration while locally paused. The compact 370 px panel has 24 px of padding below Quit.

Options has Audio, Video, Gameplay and **Controls** tabs. Controls uses a scrollable list inside the existing panel, supports live saved rebinding while paused, rejects conflicting keys and offers Restore defaults. Escape cancels key capture before leaving Options; tab changes, leaving the screen and focus loss also cancel capture. Defaults open Recruit/Build/Spells with Q/E/R, use Q/E/R for left-to-right choices (lower spells), 1/2/3 for upper spells and Tab for view. Camera, turn/cancel and hold-to-speed-up keys are also editable. See `key-bindings.md` for mappings and persistence behavior.

Quick Play, Restart and rules changes prepare behind a short "Preparing island…" screen. The decorative viewport stops immediately; data generation runs on a worker, scene construction yields between main-thread batches, and covered rendering warms the board. The cover fades before the complete entrance begins, with cosmetic tile motion updated every rendered frame. During preparation navigation and gameplay are locked. `app.start_new_game` is asynchronous: callers needing a ready session must await it or wait while `app.transitioning`. Standalone gameplay initialization remains synchronous. See `startup-performance-2026-10-12.md`.

## Scrolling decorative background

The main menu now places its 384 px-wide panel on the left, at 4.5% of the viewport width. Quick Play setup and options opened from the main menu also sit on the left; pause/options/confirmation screens retain their centered layouts. A quiet left-side vignette separates the controls from the landscape without darkening the whole map.

`src/ui/menu_background.gd` displays an isolated SubViewport texture behind the controls. It advances every application frame with `UPDATE_ALWAYS`; the old 30 FPS cap is removed. Internal resolution stays capped at 1280×820. Water/Sky, antialiasing and root-window VSync preferences apply live. Its private World3D/camera cannot interfere with gameplay, and it receives no input.

The menu uses the gameplay sun and ambient lighting, with real-time shadows controlled by the existing Video → Shadows preference. A single orthographic projection limits extra shadow passes, with an 80-unit maximum distance. Native comparison held 75 FPS with VSync both on/off shadows; uncapped throughput was ~195 FPS without shadows versus ~166 with them at 1280×820 and 8× MSAA on RTX 2060. See `menu-shadow-performance-2026-10-12.md` for frame timings and limitations.

`src/rendering/decorative_map.gd` keeps **41 pooled rows × 17 tiles**, 1.10-unit/second scrolling and a ~32° oblique camera with gentle orbit. Each row translates rigidly, but border animation is now **per tile**, with separate hashed trigger positions and durations. Entrances take 0.75–1.20 seconds; exits take 0.60–0.90 seconds. Adjacent tiles no longer fall as a row. Interior terrain, prop instances and relative positions stay unchanged; settled rows skip per-tile scheduling work. Departures compensate for camera depth to stay above the ocean.

The oldest row is recycled offscreen, refreshing only its props/terrain. `src/game/decorative_terrain.gd` calls production `KingdomRules.generate(seed, "small")` in Modern mode. A broad, gently varying neutral central belt joins generated regions into **one continuous landmass**, adding land only where there was water. Original coastlines, kingdoms, trees, sources and mountains are preserved. Enclosed single-hex holes are also filled cosmetically. Units/events are omitted. Independent deterministic chunk seeds and a pruned cache keep gameplay RNG/state separate.

`src/rendering/terrain_tile.gd` is shared by the gameplay board and menu. It uses `board_assets.gd` directly for original geometry, materials, grass, full-sized single trees, mountains, capitals, flags, shadow textures and mana sources. No custom menu saplings, recoloured vertex meshes or substitute crystals remain. Mana-source construction lives in the common assets class. The game's lighting values and prop shadow textures are retained, with costly real-time shadows disabled. Actual generated island-local coordinates are used for asset decoration/colour variation, bounding material growth while matching gameplay.

The background is active only on Main, Quick Play setup and options originating from Main. Starting a session disables its processing and rendering, and hides its texture. Pause, defeat, gameplay options and level departure do not reactivate it. Returning to Main resumes the existing strip and any in-progress border animation; it does not create another decorative world.

All **16 suites passed**, followed by **1,437 targeted background checks** after the final counter guard. Tests cover connectivity across seams, independent neighbour flight states, stable interiors/props, generator-cell preservation, bounded caches, uncapped 120 Hz advancement, FPS/F3 controls and menu/match lifecycle. A native warmed preview measured **75 application FPS / 75 menu FPS** on this host; this is an observed run, not a hardware-independent guarantee.

## FPS overlay

`src/ui/fps_counter.gd` is an app-owned CanvasLayer above menus/gameplay. It shows drawn-frame FPS and derived average frame interval in the top-right, plus an active menu-background rate. Both counts use RenderingServer.frame_post_draw, sampled every 0.25 seconds; disabled menu rendering is not counted. **F3 toggles it**, including during pause, without changing Video preferences or frame limits. No 60/75 FPS cap is added; VSync and display settings still govern presentation.

Preview with `tools/menu_preview.gd`, optionally adding `-- --water`, `--sky`, `--evolving`, `--setup` or `--small-window`. Generated images are stored under `artifacts/`.

Current warmed still: `artifacts/menu_main_evolving_water.png`. The previous video predates the connected landmass, individual timing and full-refresh rendering. `tools/menu_preview.gd` waits through startup warmup so its FPS readouts are meaningful. `tools/menu_scroll_preview.gd` remains available for a fresh motion capture when authorized.

The top-right Pause button can freeze any player or opponent phase. Escape in gameplay gives cancellation priority to selection, placement, menus and unfinished player movement. Escape with no pending action requests Pause. From Pause, Escape continues; from Options or quit submenus, it backs up one level. The viewport marks these Escape events handled to avoid immediately opening and closing pause during the same key event.

Pausing uses `SceneTree.paused`. Unit tweens, camera processing and faction hold timers are bound to the gameplay scene. Interface audio and preferences remain active. Returning to the main menu marks the old session closing, cancels its motion playback, waits for its current coroutine to unwind, and frees it. This avoids stale callbacks mutating a new game. Scene environments and camera ownership are released during disposal.

After the island departure, a temporary full-screen snapshot holds the last rendered frame throughout disposal. It stays until the main menu or returning editor has drawn, preventing the viewport's gray clear color from flashing between scenes. Restart hands this snapshot directly to the preparation cover. Navigation remains locked until the destination is ready, and the snapshot is then released.

Video preferences live in `user://video_settings.cfg`, managed by the `Video` autoload. Resolution changes use supported window sizes; fullscreen uses native display size. VSync, viewport MSAA and shadow controls apply live. Preferences are debounced and flushed on exit. Headless checks skip OS window operations but still validate preferences and viewport quality. Updating a graphics option does not unnecessarily resize the window.

The Video page also offers **Follow active kingdom**, enabled by default. Each opponent phase starts a gentle camera pan toward its territory; the player phase returns to the selected kingdom. The pan preserves zoom and camera angle, and its bound tween pauses with gameplay. Manual camera movement cancels following for the remainder of the current turn. Disabling the preference immediately stops any active pan.

**Animate level transitions**, also enabled by default, controls tile arrival on session creation and departure on victory or defeat. `board_transition.gd` moves whole tile nodes, including their structures and static soldiers, with staggered board-bound tweens. Camera-relative offsets keep the endpoints outside the viewport at any supported angle; departure stays above the water plane, with a slight lift to prevent intersecting surfaces flickering. No authoritative cells, resources or random state change. Entrance locks gameplay and camera navigation while Pause remains available. Disabling the option finishes the active transition even from paused Options. Session disposal cancels tweens before freeing their tiles; completed sessions clear overlays and hide inactive bottom controls while keeping Pause/Restart/Quit accessible.

Defeat is a distinct modal screen with **Restart level** and **Main menu**. The controller waits until its current turn playback is idle, emits the defeat request once, and pauses the intact island. Escape and Continue cannot dismiss the popup. Selecting either destination hides the popup and unpauses only to play departure; navigation remains locked. With animations disabled, the same choices complete without the animation delay. Victory retains its automatic departure.

`depart_current_game` is shared by Restart and Main Menu. `play_level_departure` first marks the controller closing, stops camera/movement, and lets pending turn coroutines unwind. The visible board then plays its exit before the application retires the old scene. Restart captures the seed before departure and starts entrance only after exit finishes. An island that is already departing after victory finishes that existing animation; an already departed island is not replayed. This avoids old and new tile animations overlapping or a completed island briefly reappearing.

The Gameplay page controls movement indicators and language. All sessions use the same rules, including provinces, mana and surrender. Restart keeps the current seed. See [modern-rules.md](modern-rules.md) for gameplay behavior.

Enemy commands commit before their animations play. To keep the next-turn income forecast aligned with visible events, the board signals changes at attack impact and occupation. The controller rebuilds a temporary economy from the visible cells and the kingdom treasury snapshot preceding the batch. House bonuses and defender upkeep disappear at impact, while province income changes on occupation. This temporary model never changes authoritative game state.

Game saving/loading is intentionally absent. A future versioned save-state loader can enter through the application/session boundary without storing UI state or camera scene nodes in the game rules. Audio/video preference files are not game saves.

The pause menu offers **Restart**, with confirmation before progress is reset. Back or Escape returns to Pause without changing the level. Confirming captures the current rules' `level_seed`, retires the old session safely, then creates a fresh game with that seed. Generation uses a stored nonnegative 32-bit seed even for random levels, so restart never accidentally treats a signed seed as the random-generation sentinel. Navigation is briefly locked during replacement. The original map, starting territory, troops, treasuries, turn and random sequence are restored; user audio/video preferences are preserved. Restart is absent from Options.
